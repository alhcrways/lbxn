# 本地好友通信（开发版本）

v1.0.4 包含好友消息客户端。使用时需要双方连接同一个通信服务端；旧的 1.0.3 EXE 不包含此功能。

## 已实现

- 右键小新 → **好友消息**，或托盘 → **好友消息 / 加好友**。
- 首次连接时设置昵称，生成十位好友码；下次启动自动恢复同一身份。
- 输入朋友的好友码发送申请；朋友同意后双方可以聊天，也可以忽略申请。
- 文字消息双向收发、未读数、消息持久化、离线消息同步、断线自动重连。
- 新消息/申请在小新旁边显示信封按钮；系统通知可点击打开信箱。
- 关闭信箱只关闭窗口，后台仍然接收消息；退出桌宠或断开连接后不再接收。
- 好友聊天和 AI 聊天完全独立，不使用任何模型或 API Key。
- 窗口沿用便利贴的浅蓝、奶油黄、绿色和棕色描边；可调整窗口大小。

## 在一台 Windows 电脑模拟两个人

开发者需要 Node.js 20.3 或更新版本，以及项目依赖（首次运行 `npm ci`）。

在项目根目录的第一个 PowerShell 窗口运行：

```powershell
npm run social:server
```

默认只监听本机 `http://127.0.0.1:4317`。保留这个终端运行。

在第二个 PowerShell 窗口先构建，再启动小红：

```powershell
npm run build
npm run start:alice
```

在第三个 PowerShell 窗口启动小蓝：

```powershell
npm run start:bob
```

两个测试身份有独立的数据目录，不会覆盖日常桌宠的数据。请勿再并行执行构建，以免覆盖另一个实例正在使用的文件。

1. 分别右键两个小新，打开“好友消息”。
2. 两边的服务地址都填 `http://127.0.0.1:4317`，昵称分别填写“小红”“小蓝”，点击连接。
3. 复制小蓝的好友码，在小红的信箱左上角输入并点“添加”。
4. 小蓝收到申请后点“同意”。
5. 两边点击好友名称就能聊天。Enter 发送，Shift+Enter 换行。
6. 关闭一个信箱后发送消息，检查小新旁边的未读信封；重新打开即可查看。
7. 退出小蓝桌宠，小红继续留言；再次启动小蓝并连接，可以收到离线留言。

`npm start` 仍然使用正常身份；`start:alice` / `start:bob` 仅用于测试。如果想为测试身份换一个名字，可直接在“通信连接设置”中修改昵称后重新连接，好友码不变。

## 两台电脑在同一局域网测试

服务端只需在其中一台电脑启动。PowerShell：

```powershell
$env:SOCIAL_HOST = '0.0.0.0'
npm run social:server
```

假设这台电脑的局域网 IP 为 `192.168.1.10`，双方客户端都填写 `http://192.168.1.10:4317`，其余步骤相同。另一台电脑的 `127.0.0.1` 指向自己，不能用来连接朋友的服务。

需自行确认双方网络可达、TCP 4317 端口可访问。HTTP 仅用于可信本机/局域网测试。跨家庭、学校或公司网络时，需要把同一通信服务部署在双方都能访问的服务器上，并通过 HTTPS 提供服务；仅运行两个 EXE 不会自动穿透 NAT。

## 服务配置与数据

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `SOCIAL_HOST` | `127.0.0.1` | 服务监听地址；局域网测试使用 `0.0.0.0` |
| `SOCIAL_PORT` | `4317` | 服务端口 |
| `SOCIAL_DATA_FILE` | `.social-data/server.json` | 服务端持久化文件 |
| `SHINCHAN_PROFILE` | 未设置 | 客户端隔离测试身份，如 `alice` / `bob` |

- 服务端使用 Node.js HTTP 长轮询，不需要额外的 npm 运行时依赖。`npm run social:build` 生成 `dist-social/server.cjs`，可单独运行 `node dist-social/server.cjs`。
- 同一数据文件只能由一个服务进程使用。请定期备份服务器数据；文件损坏会拒绝启动，不会自动覆盖。
- 此版本最多 500 个身份，每对好友保留最近 500 条消息，未读数也以保留的消息为准。定位是小范围测试，还不适合大规模开放注册。
- 好友关系和消息保存在服务端。消息不是端到端加密，服务管理员能访问数据；公网需使用 HTTPS。
- 客户端身份令牌仅由 Electron 主进程持有，并通过 Windows 系统加密保存在 `userData/shinchan-pet-data/friends-identity.bin`；不会发送到 AI 厂商，不会暴露给消息页面。
- 测试身份的用户目录为 `%APPDATA%/shinchan-pet-profiles/alice`、`bob`。不要删除或公开身份文件；当前没有账号找回/跨电脑迁移界面。
- 切换通信服务地址会使用对应服务的独立身份；换回原地址可恢复原好友码。服务端令牌仅保存 SHA-256 摘要，客户端令牌不会写入仓库。
- 发送失败时输入内容保留，点击发送可重试同一条消息；服务端按消息编号去重。应用退出前尚未成功发出的草稿不保证保存，请先确认发送成功。
- “已发送”表示服务端已保存；未实现好友在线状态和对方已读回执。界面中的未读数是自己未查看的消息数。

## 验证

```powershell
npm run typecheck
npm run test:social
npm run test:social:ui
npm run build
```

`test:social` 会用真实的本机 HTTP 服务和两个客户端验证好友审批、双向消息、离线恢复、去重、权限隔离和断线重连。`test:social:ui` 在 Windows 上使用隔离的 Electron 身份，验证真实 preload、窗口输入、未读提醒、安全文本显示和布局；不会使用正常桌宠账号，截图在 `output/social-ui/`。
